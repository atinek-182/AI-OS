### RECOMMEND (Recommended Architectural Strategy)
- **Option A: 10-Phase Direct Sub-Vault Routing Map & Dynamic Frontmatter Triggers [RECOMMENDED]**
  - **Structure**: Map each of the 10 execution phases in `website-design-engine/SKILL.md` directly to its corresponding sub-vault index file (`01` through `07`).
  - **Mechanics**: When executing Phase 1 (Color & Aesthetics), the agent reads `references/awwwards-research-vault/01-design-principles-and-aesthetics/INDEX.md`. When executing Phase 2 (Grid & Typography), the agent reads `02` and `07`. When executing Phase 4 (Motion & Shaders), the agent reads `03` and `04`. When executing Phase 5 (Anti-Slop & Quality QA), the agent reads `06`.
  - **Rationale**: Guarantees zero token waste by loading sub-vault context strictly on-demand per phase while preserving 100% depth across all 200+ vault files.

### ASK (Operator Preference Inquiry)
- **Option B: Standalone CLI Query Bridge (`scripts/awwwards_vault_query.py`)**
  - **Structure**: Create a CLI script that searches sub-vault YAML frontmatter and extracts specific GLSL shaders, grid math formulas, or GSAP motion snippets via terminal commands during web builds.
  - **Trade-off**: Requires running subprocess terminal commands during agent execution, adding shell execution overhead.

- **Option C: Single Monolithic Creation Guide Consolidation (`AWWWARDS-MASTER-CREATION-GUIDE.md`)**
  - **Structure**: Merge all 7 sub-vault summaries into a single monolithic reference document.
  - **Trade-off**: High risk of token truncation and missing deep code extracts or fragment shader math.
